# Build, don't only instrument

```
A TURN THAT PRODUCED A CLEANER RECORD AND NO NEW CAPABILITY HAS DONE FILING.
```

Checking and tidying always succeed: a checker runs and prints something, a summary always reads well. The real work (a model
that does more, an experiment that answers the question, a result the owner can use) can fail, so a long-running agent drifts
toward the comfortable side. The drift is structural, not a lapse of discipline, which is why it needs an explicit check.

## The discriminator

At the end of a turn, one question: **did this turn add a capability, or only a check on capabilities that already exist?**

| This is a build | This is an instrument |
|---|---|
| A function, model or analysis that does something new, with its test and its null | A gate that scans for the shape of such functions |
| A mechanism swept across the missing parameter | A note that the parameter is missing |
| A verdict with the replacement named | A wall, a ceiling, a "cannot be measured" |

Instrument work is legitimate and every project needs some. It is not legitimate as most of a session. If the last three things you
did were in the right-hand column, the next one is in the left-hand column.

## The end-of-turn rule
Name the capability that exists now and did not before. If you cannot, the turn is not finished, it is merely comfortable; pick the
next step from `ROADMAP.md` and do it. Stop to ask the owner only for a decision that is genuinely theirs.
